# Strategy Notes

Purpose: describe planning guidance, experience notes, recovery suggestions, and score-oriented strategy, as a static fragment in the Brain prompt.

[Notes]
1) If `is_held=true` in agent_state, it means an item is currently held. You must first navigate to a placement platform point (such as Plate / Side Table / Countertop and other placeable points), then execute put-down/placement, and then re-navigate to pick up other items.
2) When you need to execute an item pick-up action, if an item is currently held, you should first put down the item in hand, then proceed. Or place it properly after use.
2.1) Handle "held-item occlusion": when `agent_state.is_held=true` and the held object (especially bottles/pots/large containers) blocks the crosshair/front view, prefer putting it down or switching to an unoccluded viewpoint before the next pick-up. Do not repeatedly retry `pick_up` under obvious occlusion.
2.2) If pick-up fails (for example `pick_up_post_check_failed:not_holding_after_click` or `post_check_failed:pick_up_not_holding_item`), it is recommended to use visual signals for recovery: re-check `is_on_screen`, centering (`screen_x/screen_y`), and distance, then prefer "re-navigate + micro-view alignment + retry" instead of blind repeated clicks.
2.3) Avoid global staging. Do not gather or spread out many future-use tools/containers just to keep hands free. Only stage items that are required for the current recipe subtask or the next immediate interaction. Empty container staging is setup only, not scorable progress by itself.
2.4) If `task_progress`, precondition feedback, or visual anomaly feedback indicates a current subtask, blocker, or warning, prioritize resolving that concrete issue before convenience actions such as broad staging or speculative preparation for later recipe steps.
2.5) Once a required bowl/plate/pot/pan for the current subtask has already been acquired or staged, the next planning rounds should normally switch to ingredient acquisition, cutting, pouring, cooking, transfer, or submission-related progress. Do not keep acquiring or rearranging same-role empty containers unless the current one is unusable, missing, wrong, or blocked.
3) Do not only pick items: after obtaining ingredients, they must be processed according to the recipe (cut/fry/bake/mix, etc.), and after operations, outputs should be consolidated into the same chosen serving vessel. Keep container choice stable; avoid turning one chosen vessel into many staged duplicates.
4) Check `agent_state` before actions: if currently in pouring/sprinkling/cutting or other modes, either execute the corresponding skill action, or exit that mode before other operations; determine whether crouching/standing is needed based on posture. Note that `auto_navigation` already automatically includes crouch/stand decisions according to item height position.
5) Container selection must remain consistent: once a certain container/plate is determined as the carrying container for the current process, subsequent related operations should keep using this container; do not switch with view changes. Only reselect and update `active_containers` (recently used list) and `active_container` (current container) when the container is unavailable/lost or task requirements need extra tools.
6) The agent can carry multiple items at once by holding a container, but too many items can easily drop, so be careful.
7) Failure recovery priority: retry (small parameter perturbation) -> switch skill/switch path -> fallback to safe state -> optional reset.
8) If the selected instance_id causes navigation/interaction failure for 2 consecutive attempts: do not loop retrying the same instance_id; choose another instance_id in `candidates` and try again.
9) If feedback shows `error=invalid_target_name`: do not repeat the same target string; prioritize `mapping_suggestions` in feedback, or call `list_supported_items()` first to find available canonical target names and then call `auto_navigation(target=...)`.
10) Acquisition list: Chili Pepper Source; Cucumber Source; Tomato Source; Jalapeno Source; Lemon Source; Shelf; Burger Bun Source; Bun Bottom Source; Bun Top Source; Apple Source; Red Potato Source; Onion Source; Garlic Source; Cob of Corn Source; Broccoli Source; Bread Source; Parsley Root Source; Button Mushroom Source; Red Bell Pepper Source; Beetroot Source; Eggplant Source; Green Bell Pepper Source; Yellow Bell Pepper Source; Potato Source; Whole Ginger Source; Red Cabbage Source; Zucchini Source; Scallion Source; Horseradish Source; Parsnip Source; Orange Source; Carrot Source; Pumpkin Source; Small Plate Stack; Plate Stack; Square Plate Stack; Deep Plate Stack; Plate Stack; Casserole Stack; Bowl Stack; Large Plate Stack.
11) If 5 consecutive steps are `auto_perception` / `query_scene_objects` / `list_supported_items` (any combination), the next step must choose a "real physical action" to execute (such as `auto_navigation` / `pick_up` / `open_door` / `place` / `pour` / `sprinkle` / `cut` / `toggle`, etc.); continuing perception/retrieval loops is forbidden. If necessary, directly use `gui_buy_new_item(...)`.
12) Score priority: final score mainly depends on the final submitted container content and its state, including seasoning ratio, heat-treatment method and duration, food-processing procedure (e.g., cutting/mixing/cooking flow), and final temperature. If the final submitted container has no scorable content, it usually gets no score; if it contains relevant and partially correct content for the target dish, it may still receive partial score items even when not fully matched.
12.1) Build the scorable dish skeleton early: before spending many steps on seasoning tweaks or small liquid adjustments, prioritize adding the primary recipe-defining components into the final container/serving vessel (for example the main protein, key produce, or required major subcomponent). These core components usually increase score more than fine-grained seasoning/liquid optimization when they are still missing.
12.2) If the current final container still lacks one or more core dish-defining components, do not over-invest in low-value polish (extra sprinkles, tiny pours, repeated micro-adjustments). First make the dish clearly identifiable as the target recipe, then refine seasoning, temperature, and presentation.
13) If after multiple mouse/keyboard perception actions, view-adjustment actions, or movement actions the camera pose still does not change, assume the agent is likely stuck in a mode or interaction state. In that case, exiting the current mode becomes the highest priority; use right mouse button by default, and any equivalent action that reliably exits the mode is acceptable.
14) Query-to-action constraint: `query_scene_objects(...)` is only an information-gathering step and does not count as meaningful physical progress or scoring progress by itself. After one or more successful queries have already provided the candidate instance_ids / availability information needed for the current subtask, the next planning round should prioritize a concrete physical operation (for example `auto_navigation`, `pick_up`, `put_down`, `toggle_switch`, `cut`, `pour`, `sprinkle`) or a concrete instance-binding retry. Repeated querying without transitioning to physical interaction is forbidden unless the previous query result was empty, insufficient, stale, or still missing a required object/category.
14.1) Score-first assembly constraint: when constructing a dish inside a container or serving vessel, first add the recipe-defining core components into the chosen final vessel, and only then spend steps on secondary components, seasoning, and small liquid adjustments according to recipe order. This does not justify repeatedly fetching, staging, or rearranging extra empty containers.
14.2) If the current final vessel still lacks a core dish-defining component, prioritize acquiring and adding that component before low-value polish actions such as repeated tiny pours, extra sprinkles, garnish-like adjustments, speculative micro-optimization, or more empty-container shuffling.
14.3) Empty-container movement constraint: picking up, moving, and placing an empty Plate / Deep Plate / Bowl / Pot / Pan is setup only. It is allowed when the current subtask immediately needs that vessel, but it should not be treated as recipe completion progress or as a substitute for ingredient processing, cooking, transfer, or assembly.
14.4) Duplicate-vessel constraint: once a suitable serving vessel or working container of the needed role has been selected and remains available, do not fetch or stage another same-role empty vessel unless the current one is lost, blocked, contaminated, wrong for the recipe, or otherwise unusable.
